Android · ELF Repair · 逆向工程

修复从内存中 dump 下来的 SO 文件

SoFixer 重建 ELF 的 section headers、program headers 与重定位信息， 让一份从进程内存里 dump 出来的 Android SO 重新可被 IDA 等工具正常分析。 现已提供面向 AI 的结构化 CLI。

7f 45 4c 46 .ELF magic — 每个 SO 的第一行字
查看 CLI 用法 快速构建 源码

01它做什么

运行中的 SO 被 loader 修改过后，其 ELF 结构已不再是磁盘上的样子：section header table 丢失、 program header 的文件偏移与虚拟地址错位、重定位项指向的是绝对地址。直接把内存 dump 成文件， IDA 打开是一片混乱。SoFixer 把这三层结构还原回去。

RebuildPhdr

修正 program header：p_filesz 对齐到 p_memsz，p_offset 还原为 p_vaddr。

RebuildShdr

从 dynamic 段推断并重建整张 section header table：.dynsym / .dynstr / .hash / .rel.dyn / .plt …

RebuildRelocs

依据 dump 基地址，把重定位项里的绝对地址减回相对地址。

面向 AI 的 CLI

SoFixer-skills-CLI 输出结构化 JSON，子命令可被 AI agent 直接调用与解析。

02SoFixer-skills-CLI

新的统一入口，默认输出 JSON，便于 AI agent 与脚本解析。C++ 跨平台 32/64 双变体 

# 修复一个从内存 dump 的 SO（带基地址）
SoFixer-skills-CLI64 fix -s dump.so -o fixed.so -m 0x7db078b000

# 查看任意 SO 的结构信息
SoFixer-skills-CLI64 info -s libtest.so

# 校验修复后的 SO 是否结构有效
SoFixer-skills-CLI64 verify -s fixed.so

# 输出工具与构建信息
SoFixer-skills-CLI64 version

成功响应（单行 JSON，便于逐行解析）：

{
  "ok": true,
  "tool": "SoFixer-skills-CLI",
  "arch": 64,
  "command": "fix",
  "result": {
    "source": "dump.so",
    "output": "fixed.so",
    "input_size": 1392640,
    "output_size": 1396736,
    "rebuild_steps": ["phdr", "soinfo", "shdr", "relocs", "fin"]
  }
}
子命令作用必填
fix修复内存 dump 的 SO-s
info读取 ELF / SO 结构信息-s
verify校验 SO 结构有效性-s
version工具与构建信息—
help列出命令与选项 schema—

退出码：0 成功 · 1 业务失败 · 2 参数错误 · 3 内部错误。 所有错误都以结构化 JSON 返回，含稳定的 error.code。

03构建

# 64 位（处理 64 位 SO，生成 SoFixer64 + SoFixer-skills-CLI64）
mkdir build && cd build
cmake -DSO_64=ON ..
cmake --build . -j

# 32 位（处理 32 位 SO）
cmake -DSO_64=OFF ..
cmake --build . -j

依赖：CMake ≥ 3.3、C++11 编译器。无第三方库。Windows / Linux / macOS 均可构建。

04从内存 dump SO（IDA 脚本）

import idaapi
start_address = 0x0000007DB078B000
end_address   = 0x0000007DB08DE000
data_length   = end_address - start_address
fp = open('E:\\path.so', 'wb')
cur = 0
while cur < data_length:
    towrite = min(0x100000, data_length - cur)
    fp.write(idaapi.dbg_read_memory(start_address + cur, towrite))
    cur += towrite
fp.close()

拿到 dump 后，用上面的 fix 子命令，传入 -m 时的同一个基地址即可。
